# HireFlow 整体项目讲法：招聘决策 + Agent 培训陪练

## 项目定位

HireFlow 是一个面向企业人才全流程的 AI 辅助工作台，当前覆盖两个核心场景：

1. 招聘决策 Agent：将 JD、简历、面试回答转化为有证据的人岗匹配和结构化面试建议。
2. 培训陪练 Agent：将业务培训目标转化为培训内容、角色对话、行为证据评分和团队能力看板。

两个模块共用同一套产品逻辑：把非结构化任务拆成固定 Workflow，用结构化输出、证据约束、分数保护、人工复核、执行追踪和数据沉淀控制模型风险。

项目不是自动录用、自动淘汰或自动决定员工是否合格，而是帮助 HR、面试官和培训管理者获得可追溯的辅助证据。

## 面试开场：3 分钟完整版本

> HireFlow 最初是一个招聘匹配工具，但我在做原型时发现，企业人才管理的难点不只是信息处理慢，而是很多关键判断缺少统一标准和可追溯证据。例如筛选简历时容易被关键词影响，面试问题与候选人差距脱节；培训时又经常停留在听课和满意度，无法判断学员是否真的完成了目标行为。
>
> 所以我把产品定位成一个人才决策与能力发展工作台，目前有招聘决策和培训陪练两条 Workflow。招聘侧从 JD 解析开始，将岗位要求拆成带权重的能力模型，再解析和脱敏简历，逐项输出证据引用、匹配分和风险；如果必备项证据无法定位，程序会触发分数封顶和人工复核。之后系统基于岗位差距生成结构化面试题，并对真实录入或明确标注的模拟回答生成面试报告。
>
> 为了验证招聘链路，我构建了 30 条离线评测集，包括 18 条常规人岗组合、8 条边界样本和 4 条公平性反事实样本，另外对 6 条样本重复运行 3 次。结果是 30 条全部完成，岗位要求覆盖率 100%，引用定位率 95.7%，无证据高分率 0%，匹配档位符合率 73.3%，风险保护一致率 76.7%。提示注入和 AI 关键词堆砌样本分别只有 0 分和 7 分。评测也暴露出推荐策略偏保守、临界样本会出现分数漂移，以及精确字符串证据定位受 PDF 空格和换行影响。
>
> 在招聘模块之外，我把同一套 Agent Harness 扩展到了企业培训。培训管理者输入学员、主题、受众、目标和业务情境，Learning Designer 生成结构化课程和陪练场景；Roleplay Partner 严格保持客户或业务角色，与学员多轮互动；Practice Evaluator 再按具体行动、对方反应和可验证结果提取学员原话并评分。为了避免模型因为“理解、重视、马上处理”等套话给高分，我增加了证据强度和完整性封顶：无有效证据最高 30 分，只有态度表达最高 50 分，缺失行为链或练习轮次不足也会降分。最后报告自动归档，并按学员、主题、能力维度和时间形成培训看板。
>
> 两个模块让我验证了一个共通判断：企业 Agent 的核心不是多放几个聊天机器人，而是明确每个节点的输入、输出、状态、验证标准和人工边界。招聘模块已经有 30 条离线评测；培训模块当前完成了产品闭环和规则测试，但还缺专项评测集，因此下一阶段会围绕角色一致性、评分证据真实性和重复训练是否改善能力建立自动回归。

## 为什么两个模块属于同一个项目

产品主线是“人才生命周期中的高频判断标准化”：

```text
岗位定义
-> 候选人证据匹配
-> 结构化面试
-> 能力差距识别
-> 针对性培训与角色陪练
-> 行为证据评分
-> 团队能力看板
```

招聘模块解决“选人与验证”，培训模块解决“培养与复测”。共同的数据对象是岗位能力、评价维度、行为证据、人工判断和改进记录。

当前产品还没有真正打通“招聘报告自动生成培训计划”的数据链，所以面试中应称其为产品路线与模块复用，不要声称已经实现招聘到培训的全自动闭环。

## 招聘 Agent 怎么深挖

### 用户与问题

- 用户：招聘 HR 和业务面试官。
- 触发时刻：收到 JD 与批量简历、需要确定面试顺序和准备追问时。
- 失败成本：关键词误判、遗漏关键能力、问题泛化、结论无法追溯。

### 固定 Workflow

```text
JD 输入
-> 岗位能力模型与权重
-> PDF/TXT 简历解析和脱敏
-> 逐项证据匹配
-> 程序化引用验证与分数保护
-> 候选人排序
-> 差距驱动的面试题
-> 回答记录或明确标注的模拟回答
-> 面试报告与人工决策
```

### 关键产品决策

- 总分由程序按权重计算，不让模型自由给最终总分。
- 模型给出的证据必须能回到简历原文。
- 核心证据缺失时触发分数封顶和人工确认。
- 模拟回答与 HR 真实录入分开标识，避免演示数据被误当真实招聘结论。
- 系统不输出自动录用或淘汰决定。

### 已完成评测

- 30 条主样本：18 常规、8 边界、4 公平性。
- 6 条代表样本各运行 3 次。
- 规则指标 + 独立 LLM Judge + 人工预期标签。
- 主要结果：工作流成功率 100%、引用定位率 95.7%、档位符合率 73.3%、风险保护一致率 76.7%。

## 培训 Agent 怎么深挖

### 用户与问题

- 用户：培训管理者、销售/客服等需要练习业务对话的员工。
- 触发时刻：培训负责人需要将抽象目标变成可练习场景，或者学员需要在真实对客前反复练习。
- 失败成本：培训内容泛化、学员只会复述话术、评分依赖主观印象、管理者看不到团队薄弱维度。

### 为什么需要 AI

- 根据不同主题、受众和业务情境动态生成场景，固定模板难以覆盖。
- 在多轮对话中根据学员行为调整角色反应。
- 从完整对话中提取原话并判断行动、对方反应和结果之间的关系。
- 将非结构化训练记录聚合为维度、学员和主题数据。

### Agent Workflow

```text
培训 Brief
-> Learning Designer：生成课程模块、关键结论、角色画像与评分标准
-> Roleplay Partner：保持角色、多轮施压、不提前讲答案或给分
-> Practice Evaluator：引用学员原话，抽取行动/反应/结果，逐维评分
-> Evidence Guardrail：按证据强度、行为链完整性和轮次进行分数封顶
-> Report & Archive：输出建议、行动项并写入 SQLite
-> Analytics：聚合平均分、通过率、轮次、能力弱项、学员和主题趋势
```

这里应准确称为“多个专业节点组成的固定 Agent Workflow”，而不是自主规划的 Multi-Agent Team。三个 Agent 名称代表职责分离，但执行路径由产品预先定义。

### 评分保护规则

| 证据状态 | 分数上限 |
| --- | ---: |
| 具体行为证据 | 100 |
| 部分行为证据 | 75 |
| 仅态度表达 | 50 |
| 无有效证据 | 30 |

- 行动、对方反应、结果缺失 1 项时最高 75 分。
- 缺失 2 项及以上时最高 55 分。
- 学员有效表达不足 2 轮时单维最高 70 分。
- 保护后的综合分低于 60 为“需要辅导”，60–79 为“建议再次练习”。

### 培训模块当前证据

- 已实现 Brief 校验、结构化内容生成、角色对话、行为评分、证据封顶、报告归档和团队看板。
- Schema 和分析逻辑有自动化测试。
- 尚未建立培训专项离线评测集，也没有真实企业学员的前后测数据。
- 因此只能说“完成闭环原型和规则保护”，不能说“培训效果提升 XX%”。

### 培训模块下一轮评测

建议构建 24 条最小评测集：

- 8 条角色一致性：角色是否跳出设定、提前教学、直接评分或过早接受方案。
- 8 条行为证据评分：同义套话、只有态度、明确行动、对方拒绝、行动与结果冲突。
- 4 条稳定性：同一对话重复评分的分数范围和结论一致性。
- 4 条安全与边界：攻击性表达、提示注入、敏感信息、要求模型泄露评分答案。

核心指标：角色遵循率、证据引用准确率、行为链抽取完整率、无证据高分率、结论一致率、重复评分波动和人工评分一致率。

## 高频面试追问

### “这是一个招聘产品还是培训产品？”

它的上位定位是人才决策与能力发展工作台。招聘是当前主链路和验证最完整的核心模块；培训是基于相同证据评估与 Agent Workflow 能力扩展出的第二场景。面试介绍时按 70% 招聘、30% 培训分配篇幅。

### “为什么要做培训模块，会不会项目太散？”

如果只是增加课程生成确实会散。我保留它的原因是它复用了相同的底层问题：非结构化材料如何变成评价标准，模型结论如何绑定原始证据，证据不足时如何保护，以及结果如何沉淀为下一轮行动。它验证的是架构复用，而不是堆功能。

### “这是真 Multi-Agent 吗？”

不是自主规划型 Agent Team，而是固定 Workflow。Learning Designer、Roleplay Partner 和 Practice Evaluator 的职责与输入输出预先定义。这样更适合企业培训，因为路径稳定、可追踪、成本更可控。未来只有在内容检索或复杂场景研究需要动态委派时才考虑 Sub-agent。

### “培训评分可信吗？”

当前不能说已经达到专家评分水平。我做了两层保护：Prompt 要求引用学员原话并拆出行动、反应和结果；程序再根据证据强度、缺失项和练习轮次进行分数封顶。下一步仍需要人工标注的对话集校准评分器，并比较 Judge 与培训专家的一致率。

### “为什么不直接让大模型给一个总分？”

直接总分容易被表达流畅度和礼貌关键词影响。我要求逐维度输出证据，再由程序应用统一封顶规则并计算平均分，使模型负责语义理解，程序负责确定性约束。

### “项目最大的不足是什么？”

招聘部分是推荐状态偏保守和临界样本分数漂移；培训部分是缺少专项评测和真实前后测。平台层面还没有真正打通招聘识别的能力差距与培训任务生成，也缺少生产级登录、RBAC、审计、加密和数据保留策略。

## 简历表达参考

> 构建 30 条招聘离线评测集，覆盖常规、提示注入、关键词误判、信息稀疏与公平性反事实样本，并结合规则指标、LLM-as-a-judge 和稳定性复测定位推荐冲突及证据对齐 Badcase；离线集工作流成功率 100%、引用定位率 95.7%、档位符合率 73.3%。

> 将 Agent Workflow 扩展至企业培训场景，拆分 Learning Designer、Roleplay Partner 与 Practice Evaluator 节点，基于学员原话构建“行动—对方反应—结果”证据链，并以证据强度和对话完整性规则限制无依据高分，沉淀培训报告与能力看板。

以上数字必须保留“30 条合成离线评测集”口径；培训模块没有真实效果数据，不写提升比例。

## 不能说的内容

- 不能说产品已在真实企业上线或服务真实 HR、候选人和学员。
- 不能说提高招聘效率、录用质量或培训通过率。
- 不能说公平性已经解决，只能说完成两个小规模反事实烟雾测试。
- 不能把固定 Workflow 包装成自主 Multi-Agent Team。
- 不能把模型生成的模拟面试回答当作真实候选人表现。
- 不能说培训评分已达到专家水平。
