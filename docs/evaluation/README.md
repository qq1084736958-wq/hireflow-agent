# HireFlow 自动评测

## 目的

这套离线评测验证 HireFlow 在虚构和人工构造样本上的链路可靠性、证据核验、匹配档位、风险处理、稳定性和公平性反事实表现。它不代表真实招聘效果或生产合规。

## 数据集

- 18 条常规案例：3 个 JD × 6 份虚构 PDF 简历。
- 8 条边界案例：关键词误判、提示注入、笼统经历、核心能力缺失、时间冲突、信息稀疏、传统产品迁移和长噪声文本。
- 4 条公平性案例：姓名与学校名称的反事实变体。
- 6 条稳定性子集：在固定岗位模型和结构化简历下重复匹配 3 次。
- 6 条面试题子集：评估岗位关联、候选人关联和非重复性。

## 运行

确保 `.env.local` 已配置 DeepSeek，然后执行：

```bash
npm run eval
```

默认并发为 2。可以使用 `EVAL_CONCURRENCY=1` 降低速率限制风险，或使用 `EVAL_CONCURRENCY=3` 加快运行。

## 评分方式

确定性规则自动计算工作流成功率、岗位要求覆盖率、引用定位率、无证据高分率、风险保护准确率、匹配档位符合率、稳定性和公平性分数差。

LLM-as-a-judge 使用独立 Prompt 按 0/1/2 评分证据语义支持、推荐一致性、风险处理和面试题定制性，并标记过度推断。最终保留 6 条人工抽检模板用于校准 Judge。

## 输出

运行结果写入 `output/evaluation/`：

- `evaluation-cases.json`：物化后的 30 条案例定义。
- `evaluation-results.json`：完整节点输出和汇总指标。
- `evaluation-results.csv`：一行一次运行，便于筛选和制图。
- `badcases.json`：规则和 Judge 自动归因的低分案例。
- `manual-review-sample.json`：6 条人工抽检模板。
- `evaluation-report.md`：可直接用于项目复盘的中文报告。
- `checkpoint.json`：运行中断时保留的阶段结果。

## 口径边界

评测样本均为虚构或人工构造。没有真实 HR 标注时，只能表述为“30 条离线自动评测”，不能写成真实企业上线、招聘准确率、录用质量提升或无偏见证明。
